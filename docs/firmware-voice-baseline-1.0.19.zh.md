## 2. 当前人工结论

当前两块真机为 `FA20` 和 `8428`。本轮调试已经确认：

- 两个方向都能够收到并播放远端语音；
- 远端语音可以唤醒屏幕，语音结束后 UI 循环能够恢复；
- BLE 语音控制、ADPCM 上下行、Relay 转发和 ESP 播放链路可用；
- 诊断播放结束会显式注入 `RemoteEnd`，不会再把设备永久留在远端讲话状态；
- 用户将本版本标定为“语音链路可用”，允许作为架构调整的回归基线。

仍未关闭的问题：

- 常用音量档位的人声偏小，必须继续做音量体验优化；
- 当前结论不是“最终 Golden Voice 音质完成”，架构阶段不得把音量问题写成已解决；
- 还需要在后续正式收口中完成双向 60 分钟压力测试、完整 busy/断线矩阵和音量 AB。

因此，架构调整阶段允许冻结并保持当前声音行为，但 P1～P7 不得顺手修改
codec、DSP、采样率、ADPCM、队列深度或音量曲线。音量优化必须作为独立变更，
使用同一硬件、距离、语句和网络条件与本基线做 AB，并重新执行双板验收。

## 4. 冻结的控制合同

- App 通过 BLE 发送 `gateway_ready`、`ptt_granted`、`ptt_cancel`、
  `remote_begin`、`remote_end` 和 `sleep`。
- ESP 只有在 `ptt_granted` 后开始上行语音。
- `remote_begin` 会取消本机正在等待或持有的 PTT，并在熄屏/待机时唤醒屏幕。
- `remote_end` 必须清除远端讲话状态。
- BLE 所有者连接断开时必须取消本机 PTT 并清除远端讲话状态。
- 下行序号不连续、队列溢出或解码失败必须进入 drop 统计，不能播放陈旧帧来掩盖延迟。
- 当前保持半双工策略，远端播放期间不得把扬声器声音重新送回麦克风上行。

## 5. 架构调整的回归红线

出现以下任一情况即视为相对本基线回归，停止当前架构阶段并回退：

- 任一方向从“可听”退化为无声；
- 远端唤醒、`RemoteEnd`、PTT 释放或 BLE 重连失效；
- 出现持续爆音、重复播放、回廊式混响或陈旧音频堆积；
- UI/菜单在语音结束后不恢复；
- queue drop、short read/write、heap 或重连次数出现持续增长；
- OTA 签名、防降级、NVS 配对或房间状态被破坏。

音量偏小是本基线已知限制，不作为“相对本基线新增回归”；但最终发布前仍必须解决并重新验收。
